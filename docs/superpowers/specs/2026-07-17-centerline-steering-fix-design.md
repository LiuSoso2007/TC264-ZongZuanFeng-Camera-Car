# 直道蓝线与舵机左偏修复设计

## 背景

车辆正对直道时，IPS200 上的赛道蓝色中线出现“7”形，首帧图像处理后舵机由启动中位向左打角。上一版远景无效搜线截断未解决实车问题。

## 根因

1. `Camera_DrawCenterLines()` 以两行间隔连线时，把未处理的 `ImageDeal[ImageStatus.OFFLine]` 当成有效端点。该旧值会在蓝线顶部形成横向跳变。
2. CPU0 将中线偏差除以 `ImageSensorMid`，使 `Err` 位于约 `[-1, 1]`；CPU1 的 PD 仍使用 `+-5` 像素死区，因此舵机控制长期进入中位分支。
3. PD 中位被硬编码为 50 度，与已经确认的实车舵机中位 80 度不一致。启动时舵机处于正确中位，进入首帧 PD 后被改到 50 度，造成向左打角。

## 设计

采用最小根因修复，不调整电机参数、PD 参数和转向正负方向，也不修改逐飞设备库。

### 蓝线绘制

从基准行向远处绘制蓝线。每段线的两个端点都必须满足行号大于 `OFFLine`，从数据边界上排除未处理行。

### 偏差单位

CPU0 输出像素偏差：近场有效时继续使用第 50 至 52 行中心平均值，减去图像中点后直接赋给 `Err`，不再归一化。远景不足时仍使用 `OFFLine + 1` 的最后有效中心。

若基准区也无有效赛道，则将 `Err` 置零，禁止沿用上一帧打角。

### 舵机中位与限幅

将 80 度定义为唯一舵机中位校准值，舵机初始化和 PD 输出共同使用该值。保留 `Kp=0.8`、`Kd=0.4` 与 `+-5` 像素死区。

PD 输出在送入舵机前限制到 9 至 132 度，低于中位和高于中位的两个方向都保留可用范围，并与舵机驱动的最终上限一致。

## 数据流

`Get_BaseLine()` 和 `Get_AllLine()` 产生有效边界及中心，元素处理按现有逻辑修正中心；显示函数只画有效中心。CPU0 以像素为单位生成 `Err`，CPU1 使用同一像素单位执行 PD，并围绕 80 度中位输出舵机角度。

## 验证

1. 修改前建立静态回归检查，证明绘制循环会引用 `OFFLine`、`Err` 被归一化且 PD 中位为 50 度。
2. 修改后检查蓝线所有端点均位于有效行、`Err` 保持像素单位、中位常量在初始化与 PD 中一致。
3. 用边界值模拟验证负误差、零误差和正误差分别产生中位两侧及中位输出，且最终角度始终位于 9 至 132 度。
4. 检查所有修改文件为 GBK 编码且无 BOM，并执行 Git 空白错误检查。
5. 若本机缺少 ADS/TC264 编译工具，明确记录未执行固件编译，由实车烧录验证直道蓝线和舵机方向。

## 不在本次范围

不重新调整电机速度、PD 增益、摄像头阈值、赛道元素识别阈值，也不修改逐飞摄像头或陀螺仪设备函数。
