1什么是"扫线"？—— 在一行像素中找黑白跳变

"扫线"就是逐行扫描二值化图像, 在每一行中找黑白跳变的位置。黑(0)跳到白(1)的那一列, 就是赛道的边界列号。

以某行为例, 从左到右找黑白跳变 ▼
051015......707580
← 赛道外(黑)
▲ 左边线=第17列
赛道内(白) → 中线=(17+71)/2=44
▲ 右边线=第71列
赛道外(黑) →
✓ 左边线=第17列, 右边线=第71列, 中线=(17+71)/2=第44列, 赛道宽度=71-17=54列

3Get_AllLine() —— 从下往上逐行追踪边线

4什么是"补线"？—— 边线找不全时推算填上空缺

Get_AllLine 追踪到某行找不到边线时产生"丢线"。"补线"就是根据已知信息推算出丢线位置的边界列号。

方式一: 半宽推算 (单边丢线)

只找到一边时, 用已知边 + 赛道半宽推算另一边

行20: 找到Left=15, 右边界丢了!
→ Right = 15 + HW[20]
→ Right = 15 + 22 = 37(列)
→ Center = (15+37)/2 = 26
方式二: 斜率延长 (十字路口)

十字路口双边都丢线, 用前后边线斜率线性延长

行50~40: 左边线每行右移0.5列
行40~20: 十字路口, 双边全丢!
→ k = Δ列/Δ行
→ L[39] = L[40] + k 逐行延长
方式三: 拐点直连 (圆环出环)

圆环出环时边线跳跃, 从拐点向底行连直线补

行52: Left=19(底行, 已知)
行30~50: 环内, 边线不可用
行25: 出环拐点列=60
→ 行25(列60)→行52(列19)连直线
方式四: Get_AllLine 内部原位补线

追踪中单边丢线时立即用半宽补上, 让后续追踪有完整参考

行45: Right=70, 左边界没找到
→ Left = 70 - HW[45]
→ Left = 70 - 25 = 45(列, 立即补)
⚠ 风险: 补出来的边线是推算值, 连续补太多行会误差累积。策略: 单边丢→原位补; 双边丢→不补, 直接OFFLine截断; 十字/圆环→独立函数, 仅条件触发。

6+为什么"中线"是列, "前瞻"却是行？

行 决定"看多远"
每行对应车前方不同的物理距离:

行55~59: 0~30cm (太近, 来不及反应)
行40~50: 0.5~1.0m
行21~25: 1.0~1.5m (← 理想前瞻距离)
行10~15: 2~3m (图像模糊, 边线不准)
行0~5: 3m+ (太小, 不可靠)

前瞻 = 选哪几行 = 决定"看前方多远"。
速度快→选行号小的行(看更远)
速度慢→选行号大的行(看更近)
列 决定"偏多少"
每一行扫线后都产生自己的边界列号:

行52: L=19 R=73 → Center=46
行40: L=16 R=73 → Center=44
行30: L=15 R=73 → Center=44
行24: L=14 R=72 → Center=43
行20: L=15 R=72 → Center=43

不同行的 Center 可能不同——因为赛道在弯, 远处的赛道中线偏左, 近处的偏右。

中线 = 列号 = 赛道在这一行处的横向位置。
Err = Center(列号) ? 46(列号) = 横向偏移。
每行有自己的 Center(列号) —— 前瞻决定取哪几行的 Center 来算 Err
列0列30列46(中线)列60列93

前瞻 = 选行21~23 (高速模式)  →  取这三行的 Center  →  Err = (43+44+44)/3 ? 46 = ?2.3
行 = 纵向维度, 决定"取哪几行" (看多远)  |  列 = 横向维度, 决定"偏多少" (算偏差)
📌 两者的关系: 每行都有一个 Center(列号)。Center[0]~Center[59] 是 60 个列号——一条"赛道走向曲线"。前瞻就是在这条曲线上选一个点(或其附近几个点的平均), 读出该点的列号, 减去 46(图像中线), 就是 Err。选不同的行 = 看前方不同的距离 = 不同速度需要不同的前瞻距离。

8速度会影响前瞻和 Err 吗？

速度 → 直接影响前瞻 (选行)
✓ 速度是前瞻选行的唯一依据:

speed < 60 → 选行 23~25 (看近)
speed 60~65 → 选行 22~24 (看中)
speed > 65 → 选行 21~23 (看远)

速度越快 → 必须在更远处看到弯道 → 选行号更小的行。
速度 → 不直接进入 Err 公式
✖ Err 公式里没有 speed 这个变量:

Err = Center ? 46

速度不改变赛道的实际位置, 所以不改变每一行的 Center 值本身。

但有一个间接影响: 速度变了 → 选的行变了 → 不同行的 Center 可能不同 → 算出来的 Err 数值也会变。这是行选择带来的连锁反应, 不是速度本身影响了 Err。
总结:
速度 → 选行(前瞻)  →  不同行的 Center 可能不同  →  Err 值跟着变
速度 不直接 参与 Err 计算, 但 间接 影响了结果——
换了一组行, 就换了一组 Center, 就换了一个 Err。
