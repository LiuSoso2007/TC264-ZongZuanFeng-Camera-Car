# TC264总钻风摄像头车

基于英飞凌 AURIX TC264、逐飞总钻风 MT9V03X 摄像头和 IPS200 屏幕开发的视觉四轮舵机智能车工程。项目使用双核分工：CPU0 负责图像采集、赛道识别和元素处理，CPU1 负责编码器采样、电机 PI 闭环与舵机 PD 控制。

当前默认分支为 `PID-100-21S`。README 的加入没有修改该版本的车辆控制参数或赛道元素逻辑。

## 硬件与开发环境

- 主控：Infineon AURIX TC264（工程目标为 `tc26xb`）
- 摄像头：逐飞总钻风 MT9V03X，原始灰度图分辨率 `188 × 120`
- 显示：IPS200 SPI 屏幕，用于图像和运行状态调试
- 执行机构：双直流电机、双路正交编码器、50 Hz PWM 舵机
- 工程环境：Infineon AURIX Development Studio（ADS）与 TASKING 工具链
- 底层基础：逐飞 TC264 开源库和 Infineon iLLD

## 软件架构

| 模块 | 主要职责 |
| --- | --- |
| CPU0 | 摄像头帧接收、图像压缩、OTSU 二值化、边界与中线提取、赛道元素识别、转向误差发布、IPS200 调试显示 |
| CPU1 | 10 ms 运动控制周期、编码器读取、左右电机 PI 闭环、差速计算、舵机 PD 控制、停车请求执行 |
| 双核通信 | 通过带互斥保护的最新值邮箱同步 `Err` 和进环减速状态，避免同一帧误差被重复执行 PD |

图像与控制数据链如下：

```text
MT9V03X 灰度图
  -> 188×120 图像压缩为 94×60
  -> OTSU 自适应二值化
  -> 基线、左右边界和中线提取
  -> 圆环 / 十字 / 斑马线识别与补线
  -> 多行中线计算 Err
  -> CPU0/CPU1 邮箱
  -> 舵机 PD + 左右电机 PI
```

## 已实现功能

- 基于灰度直方图的 OTSU 自适应阈值，并带极端光照阈值保护。
- 将摄像头原始图压缩为 `94 × 60` 后进行逐行边界搜索和中线计算。
- 左右圆环识别与八阶段状态机：确认、接近、入环、环中、两阶段出环和恢复。
- 左圆环按车辆实际路线设计：从右上侧沿逆时针方向进环，逆时针行驶一圈后出环。
- 十字拐点识别、连续性确认和延长线补线。
- 斑马线识别；发车区域用于稳定方向，完成圆环流程后再次识别可触发延时停车。
- 图像底部全黑保护，可锁存停车请求；CPU1 随后关闭电机并让舵机回中。
- 左右轮独立 PI 速度闭环、基于图像偏差的差速控制和舵机 PD 转向。
- 进环阶段独立减速请求，圆环识别状态和控制输出通过同一帧快照同步。
- IPS200 可选调试界面，可显示图像、阈值、编码器、误差及圆环状态等信息。

## 目录结构

```text
Seekfree_TC264_Opensource_Library/
├─ .project / .cproject        ADS 工程配置
├─ Lcf_Tasking_Tricore_Tc.lsl  TASKING 链接脚本
├─ code/                       摄像头、图像算法、PID、电机、编码器、舵机等模块
├─ user/                       CPU0、CPU1 入口及中断配置
└─ libraries/                  逐飞设备库、Infineon iLLD 与相关底层文件
```

主要业务文件：

- `code/Camera.c`、`code/Camera.h`：图像处理、巡线、圆环、十字和斑马线逻辑。
- `code/Shared.h`：CPU0 与 CPU1 的误差及减速状态邮箱。
- `code/PID.c`：舵机 PD 和左右电机 PI 控制。
- `code/Motor.c`、`Encoder.c`、`Servo.c`：运动执行和反馈接口。
- `user/cpu0_main.c`：视觉处理主循环。
- `user/cpu1_main.c`：10 ms 运动控制主循环。

## 在 ADS 中使用

1. 克隆或下载本仓库，确认当前分支为 `PID-100-21S`。
2. 在 ADS 中选择导入已有工程，将 `Seekfree_TC264_Opensource_Library` 作为工程目录。
3. 确认 Debug 或 Release 配置使用 AURIX TASKING 工具链和 `tc26xb` 目标。
4. 在 ADS 中编译并烧录至车辆。
5. 首次运行前架空驱动轮，检查摄像头方向、电机方向、编码器正负、舵机中位和急停行为。

本仓库没有在 GitHub 环境中执行 ADS 编译、烧录或实车验证；最终行为必须以本地 ADS 构建结果和实车测试为准。

## 分支与历史版本

仓库保留完整历史分支，方便回看不同阶段的图像和控制方案：

- `PID-100-21S`：当前默认版本。
- `PID90-23S`：PID90-23S 阶段版本。
- `BDS300`：包含 VOFA 遥测相关阶段。
- `master`：早期主线历史。
- `codex/pure-vision-ring-fsm`：纯视觉圆环状态机开发分支。
- `codex/s-bend-straight`：弯道与直道逻辑整理分支。

同时保留 `slow-finish-v1`、`speed-40`、`speed-closed-loop-2m`、`国赛低速完赛版`、`纯净2版`、`8-12待落地版` 和 `revolution-pure` 等标签。切换版本前请先保存本地调参，避免覆盖实车校准数据。

## 修改注意事项

- 舵机中位、转角范围、电机方向、速度环和转向参数均与实车相关，不应直接照搬其他车辆参数。
- `libraries/` 为底层依赖，业务修改应集中在 `code/` 和 `user/`，不要改动逐飞 device 库。
- 图像处理帧率会影响按帧计数的元素状态机；开启大量 IPS200 文本或图像刷新后应重新观察实际处理帧率。
- 静态检查不能代替 ADS 编译与实车验证。修改圆环、十字、斑马线或控制逻辑后，应分别验证识别状态、补线结果、误差方向和最终执行输出。
